# Workflow

1. Сформулировать один ожидаемый результат. Посмотреть `git status`, профильный
   код и документацию; сохранить чужие изменения.
2. Внести минимальное связное изменение. Планы, prompts, логи и разовые ревью
   при необходимости положить в `.work/`; дополнительные инструменты не обязательны.
3. Выполнить подходящие [проверки](README.md#проверки). Для UI проверить сценарий
   вручную, для протокола — успешный запрос и ошибку.
4. Обновить профильную документацию, если поменялось поведение или контракт.
   Многоэтапное направление записать в roadmap; завершённое перенести в completed
   с кратким результатом. Для мелкого исправления отдельный roadmap не нужен.
5. Просмотреть `git diff --check`, `git diff` и staged diff. В коммит включить
   только исходники, необходимые ресурсы, lock-файлы и постоянную документацию.
   Имя коммита: `feat:`, `fix:`, `docs:` или `chore:` с конкретным результатом.

Перед пушем проверить состав ветки и remote. Не включать `.work/`, секреты,
сборки и генерируемые схемы. Не добавлять script для команды, уже доступной
через pnpm или cargo.
